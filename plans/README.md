  so every other plan's "tests pass" guarantee is local-only until it lands.
- **004 after 002**: both restructure `src/component/billing/queries.ts`;
  002's branch rewrite would conflict with 004's guards if done in parallel.
- **009 (publish) soft-depends on 002/003/004/006**: they change public query
  semantics and error shapes; publishing first would make them breaking
  changes against real consumers. 009 can be *executed* anytime but the
  operator should not actually publish until those merge.

  not code. Their implementation plans get written after maintainer review.

  `publishConfig.access` is `restricted`; 009 also sets the version/changelog
  state that 012's version gate keys off. The first automated publish should

## Findings considered and rejected

Recorded so the next audit doesn't re-derive them:

- **Uncaught `JSON.parse` in `verifyV2Event`** (`src/client/webhooks/v2.ts:33`):
  not a bug — `parseEventNotificationAsync` already parsed the identical body
  during signature verification, so the parse cannot fail.
- **Monetary `v.number()` fields lack min/max bounds**: values come from
  Stripe (the source of truth) and Convex validators have no `.min()` API;
  runtime range checks would be defensive noise.
- **"Zero test coverage for webhook processors"**: false — covered indirectly
  by `src/client/webhooks.test.ts` (1,634 lines: domain routing, trigger
  dispatchers, async hook scheduling, dedup, signatures).
- **Manual account-list pagination TODO** (`src/client/core/accounts.ts:354`):
  blocked on Stripe SDK support; nothing actionable until the SDK ships it.
- **brace-expansion moderate advisory** (`pnpm audit`): dev-only transitive
  via `shadcn > ts-morph`; addressed as a side effect of Plan 007's
  dependency move, not worth its own plan.
- **Cursor pagination for list queries**: a feature/design choice, not a bug;
  partially superseded by Plan 002 (which fixes the correctness issue). Can
  be revisited after 002 lands — its compound indexes are the foundation.
- **TypeScript 5.9 → 6.0 upgrade**: available but no concrete cost to staying
  (no EOL/security pressure); revisit when an ecosystem dependency forces it.
- **`errors.ts` double cast as a security finding**: it's a typing wart, not
  a vulnerability; folded into Plan 006 Step 4.
- **Setup CLI (`better-stripe init`)**: real friction (the example's
  `/admin/setup` page proves the flow) but the weakest-evidenced direction
  finding; deferred without a plan — revisit after publish (Plan 009) when
  external users exist to validate demand.
